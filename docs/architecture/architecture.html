Real Estate Intelligence.

A normalized, historical base of public real-estate listings with a deterministic market-intelligence layer on top — designed as an evolutionary modular monolith: strong logical boundaries (DDD bounded contexts, flat-by-aggregate modules, an Anti-Corruption Layer around every external system) with physical boundaries kept evolutionary.

1What it is.

A market-intelligence layer over public real-estate listings, built as one deployable system with strong internal walls.

Isolated contexts DDD
Nine bounded contexts. Each owns its PostgreSQL schema and is its only reader and writer; another context is reached through a facade or an event.
No lock-in ACL
Listing sources, object storage, the broker, the AI service, model providers and Keycloak each sit behind a port. Swapping one is writing an adapter.
Resilience by default Fail-safe
Transactional outbox, idempotent consumers, and one policy composition around every external call: timeout, retry with jitter, circuit breaker, fallback.
Deterministic core AI boundary
Every figure is computed by backend code, dated and traceable to its source. A model routes a request and explains a result; it never produces one.
The one rule. The logical boundary is always strong; the physical boundary is evolutionary. Contexts, contracts, state ownership and the anti-corruption layer are fixed from the first story. Whether a context ever gets its own deploy or database is an operational choice made later, on its own metrics.
Status. The repository is in its foundation phase: four applications, four packages, one deterministic rule. This document draws the target that ADRs 0011 to 0014 set; it is a reading of the spec and the ADRs, and an accepted ADR wins wherever the two disagree.

2Domains — DDD.

Subdomains classified as Core, Supporting or Generic; everything external is reached only through the anti-corruption layer.

How the contexts relate

Upstream Downstream Relation
collection properties Customer and supplier: a parsed snapshot becomes a listing observation.
locations properties market Open host service: places are resolved and referenced by identifier.
properties market alerts audit Published language: listing and property events.
properties comparables Customer and supplier: candidates through the facade.
ask AI service A port outwards; typed tools and the checkpoint saver calling back.

Two decisions worth reading twice. Property and Listing stay distinct entities but share one context: they share a vocabulary, every screen reads them together and a merge moves listings between properties. And "run" means a collection run in collection and a natural-language run in ask, which is exactly the kind of word that marks a boundary.

3Principles.

Modular principles win every conflict with structural ones.

BoundariesA context exports a facade, its DTOs and its events. Nothing else is importable.
State isolationOne schema per context. No foreign key and no join crosses it.
Explicit communicationA facade for a query, an event for a change.
ReplaceabilityEvery external system behind a port named for the capability.
Fail independenceTimeouts, breakers, bulkheads and a named fallback per dependency.
ObservabilityOne trace from the request to the model call, with no payload in it.
Co-locationOne aggregate, one folder. The layer is a suffix.
Shallow depthContext, aggregate, file. A folder needs two or more files.
Proportional depthRich models in the Core, thin ones where no invariant exists.
DeterminismFigures come from code. A model routes and explains.
Where structure yields. Full co-location would put one context in one package. Here the four layer packages stay, because they make the inward dependency a compile-time fact and keep the AI service away from infrastructure. A context is therefore the same folder name in each package: modular before structural.

5Bounded contexts.

Tactical depth in proportion: rich aggregates where the product earns its value.

Diagram 3 — A rich aggregate of the Core. Methods speak the domain language; history is a child of the root, not a side table someone else writes.
Class Intensity What it looks like here
Core Full Listing with its history and invariants; Property with its asking-price rule; Match with probability, evidence and the 0.90 and 0.50 thresholds; figures as pure, documented rules.
Supporting Moderate The run state machine (at most three pending per thread, expiry, pause and resume); the source review that gates collection; a suppression that outlives the data it removes.
Generic Minimal An audit entry is a row. A principal is what Keycloak says it is.
  • One transaction changes one aggregate. A rule that spans aggregates is eventual, through an event.
  • An aggregate refers to another by identifier, never by object reference.
  • Methods are named in the domain language: observe, markRemoved, attachTo, not setStatus.

6Anti-Corruption Layer.

The context declares what it needs; the adapter translates the vendor in and out.

Diagram 4 — Ports & Adapters. The context declares the port in its own language; swapping a vendor is writing one adapter.
Port Context Adapters Phase

RawSnapshotStore collection S3-compatible storage: MinIO, R2 MVP

  • No vendor type, error, status code or identifier format crosses a port. An adapter maps failures to a closed set: transient, rejected, unauthorized, exhausted, forbidden by policy, cancelled.
  • ListingSource both fetches and parses, so a stored snapshot is parsed again after a parser fix without one request to the source.
  • Every port has an in-memory fake; unit tests never open a socket.
A source is not an obstacle to get around. A login wall, a CAPTCHA, a block or a rate limit is a "forbidden by policy" failure. It is never retried: the circuit opens at once and the source is disabled until its register entry is reviewed.

7Events and the transactional outbox.

Synchronous inside an aggregate; an event, written with the change, across contexts.

Diagram 5 — Transactional outbox. The change and its event commit together or not at all; publishing is a separate, repeatable step.
Event Consumed by To
collection.snapshot.stored collection Parse the stored snapshot.
collection.snapshot.parsed properties Apply the observation to the listing.
collection.run.completed properties alerts Mark unseen listings removed; evaluate the rules.
collection.listing.suppressed properties market audit Erase the listing, its fingerprints and its facts.
properties.listing.created .price-changed properties market alerts Resolve the entity; record price facts.
properties.listing.removed .reappeared market alerts Close or reopen time on market.
properties.property.asking-price-changed market comparables Count each property once at its asking price.
properties.match.decided audit Record the decision and its evidence.
market.snapshot.computed alerts Evaluate the rules on market value.
ask.run.requested ask in the worker Execute the run, serially within its thread.
  • Names follow context.aggregate.action. A payload carries primitives and identifiers: no entity, no vendor type, no credential, no personal data.
  • An event has an identifier, a type and version, the aggregate identifier, the time it occurred and the trace context, so one trace follows a change across the broker.
  • A consumer that needs more than the payload asks the facade of the publishing context.
  • One queue per consumer, so a slow one never delays another.
Not everything is an event. A listing and its history commit together, inside the aggregate. A removal is a Suppression committed in collection before anything is erased, so no run in between can restore the listing.

8Front to back.

The frontend knows one thing about the backend: the versioned contract.

Diagram 6 — Front to back. One versioned contract; request and response over HTTP, progress pushed over SSE.
  • /api/v1 is the only surface. /health and /ready stay outside it: they are operational, not product.
  • A write that creates something carries an Idempotency-Key; a repeat returns the first result.
  • A thread is reached with its opaque capability in the MVP. Protected operations stay unexposed until Keycloak validates a session.
  • No generated client and no data-fetching library yet (ADR 0006): the contract types are shared at compile time through @rei/contracts.

9Module layout — flat by aggregate.

The folder is the business concept; the layer is the suffix and the package.

Diagram 7 — A context, flat by aggregate. The same two names, context and aggregate, lead to every file of a concept.
Suffix Layer Package
.entity.ts .vo.ts .events.ts Domain: behaviour, invariants, facts @rei/domain
.service.ts .handler.ts .facade.ts Application: use cases, event handlers, the public face @rei/application
.repository.ts .port.ts Application: what the context asks of the outside @rei/application
.pg-repository.ts .adapter.ts Infrastructure: explicit SQL and vendor translation @rei/infrastructure
.dto.ts The versioned HTTP shapes @rei/contracts
.controller.ts .consumer.ts .job.ts .module.ts Delivery and composition apps/api apps/worker
  • Never a folder named entities/, services/, repositories/ or dto/.
  • Every context is flat. None meets four of the six criteria for sub-domains: persona, authorization, execution model, scaling, deployment, failure isolation.
  • Tests stay beside the file they cover, as *.test.ts, and use hand-written fakes of the ports.
  • The boundaries are checked by import zones in the single root ESLint configuration, added with the first context that holds code.

11Data ownership.

One database is fine. Shared tables are not.

CoreSupportingGenericplatform
Diagram 10 — One database, one schema per context. No foreign key crosses a box; table names are indicative and settle in the stories.
  • A context is the only reader and writer of its schema. market keeps its own price facts, fed by events, instead of joining the tables of properties.
  • A reference to another context is an identifier, validated in code. Identifiers are UUID version 7, generated by PostgreSQL 18.
  • Explicit SQL through pg, no ORM (ADR 0003). A migration touches one schema and is named NNNN_<context>_<description>.sql.
  • Timestamps are UTC. The pair of source and identifier at the source is unique, which is what makes ingestion idempotent.

12Resilience.

Compose, do not substitute: each layer handles a different kind of failure.

Diagram 11 — One composition for every call that leaves a process. Retries live in exactly one layer; each real attempt consumes a limiter token.
Adapter Retried Idempotency key Fallback when the breaker is open
Listing source 429, 5xx, timeout, network Source and identifier at the source Pause the run at its checkpoint; the source is degraded.
Raw snapshot store Timeout, network, 5xx Content hash, used as the object key Fail the job for redelivery; nothing is parsed.
Event publisher Timeout, network, missing confirm Event identifier The row stays pending in the outbox.
Run executor Nothing at the HTTP layer; redelivery repeats the step Run identifier and step The run fails with a typed reason.
Checkpoint saver, tools Timeout, network, 5xx on safe calls Thread and checkpoint identifiers The node fails; the run fails or is redelivered.
Jev 429, 5xx, timeout, network None: a pure decision The heuristic decides, marked degraded, under the same 0.85 gate.
Generative model 429, 5xx, timeout, network None: an explanation The secondary model, only on a route with verified Zero Data Retention.
Identity provider Key-set fetch None: reads only The last key set within its lifetime, otherwise refuse.
  • One retry layer. An adapter makes one attempt. A redelivered message is the retry of a job and is not multiplied by a retry inside the adapter.
  • Retry budget. Retries are capped at about one tenth of the calls in a rolling window: they are load multipliers.
  • Breaker. Opens on the error rate of a sliding time window with a minimum number of calls, and on slow calls. One logical operation is one outcome.
  • Starting values. Base 100 ms, factor 2, cap 30 s, three to five attempts for service calls; base 1 s and cap 5 min for listing sources; breaker at half of at least twenty calls failing in ten seconds. They live in named configuration and are calibrated with fake clocks.
  • Telemetry. Retry, timeout, bulkhead rejection, breaker transition, rate limiting and fallback are typed events per dependency, with no payload.
Privacy does not degrade. A route that cannot verify Zero Data Retention fails closed. No fallback ever moves user text to a less private route, and a cancelled call never turns into a heuristic or generated answer.

13Real time.

SSE for progress: plain HTTP, automatic reconnection, no extra infrastructure.

Diagram 12 — Real time. The stream is a view over a table, which is what makes it resumable and safe across instances.
  • Events are versioned and every stream ends in an explicit terminal event: completed, failed, cancelled or expired.
  • Reconnection uses Last-Event-ID and the same capped backoff with jitter as every other call.
  • Valkey stays optional with no consumer. Pub/sub is added only if LISTEN/NOTIFY cannot reach the number of API instances in use.

14Evolution.

Start as one system; promote a part only when its own numbers ask for it.

Diagram 13 — Evolution. Every stage keeps the logical boundaries of stage 1; only the physical ones move, and only on evidence.
  • What makes stage 2 and stage 3 cheap is already in stage 1: no shared tables, no direct calls across contexts, events on a broker, adapters behind ports.
  • The first candidates are collection, whose load follows the sources and not the users, and ask, whose latency follows the model providers.
  • "It feels big" is not a trigger. Queue time, CPU contention, a different release cadence or a failure that must not spread are.
